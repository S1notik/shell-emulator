# Эмулятор оболочки ОС

Практическая работа №1 по дисциплине «Конфигурационное управление», вариант 20.
РТУ МИРЭА, 3 семестр 2026/2027 учебного года.

Эмулятор командной строки UNIX-подобной операционной системы с графическим
интерфейсом. Написан на Java с использованием Swing, внешних зависимостей
не требует.

## Этапы работы

| Этап | Содержание |
| --- | --- |
| 1. REPL | Графический интерфейс, разбор строки, команды-заглушки `ls`, `cd`, `exit` |
| 2. Конфигурация | Параметры командной строки, выполнение стартового скрипта |
| 3. VFS | Виртуальная файловая система в памяти, загрузка из директории |
| 4. Основные команды | Логика `ls` и `cd`, команды `cal`, `echo`, `tail` |
| 5. Дополнительные команды | Команды `mv` и `mkdir`, изменяющие состояние VFS |

В разделах ниже номер этапа указывает, на каком этапе появляется
соответствующая функциональность.

## 1. Общее описание

Окно эмулятора состоит из области вывода, имитирующей терминал, и панели ввода
с полем команды и кнопкой отправки. Команда выполняется по нажатию Enter или
по клику на кнопку.

Заголовок окна и приглашение к вводу формируются из реальных данных
операционной системы, в которой запущен эмулятор:

```
Эмулятор - [username@hostname]
username@hostname:~$
```

Проект разделён на пакеты с одной ответственностью у каждого:

| Пакет | Отвечает за | Этап |
| --- | --- | --- |
| `parser` | Разбор введённой строки на команду и аргументы | 1 |
| `commands` | Выполнение команд и их поиск по имени | 1 |
| `gui` | Окно, ввод, вывод, связывание остального вместе | 1 |
| `config` | Разбор параметров командной строки, выполнение стартового скрипта | 2 |
| `vfs` | Виртуальная файловая система в памяти | 3 |

Граница между пакетами односторонняя: парсер ничего не знает о командах,
команды ничего не знают о парсере, и ни те ни другие не знают о Swing.

Все операции с виртуальной файловой системой выполняются в оперативной памяти.
Исходная директория на диске не изменяется и не распаковывается.

## 2. Описание всех функций и настроек

### 2.1. Команды эмулятора

| Команда | Аргументы | Поведение | Этап |
| --- | --- | --- | --- |
| `ls` | путь, необязателен | Выводит содержимое каталога VFS | 4 |
| `cd` | путь, не более одного | Меняет текущий каталог VFS | 4 |
| `exit` | не принимает | Завершает работу эмулятора | 1 |
| `cal` | месяц и год, необязательны | Выводит календарь на месяц | 4 |
| `echo` | любое количество | Выводит аргументы через пробел | 4 |
| `tail` | путь к файлу, число строк | Выводит последние строки файла из VFS | 4 |
| `mv` | источник и назначение | Перемещает файл или каталог внутри VFS | 5 |
| `mkdir` | путь | Создаёт каталог в VFS | 5 |

На этапе 1 команды `ls` и `cd` являются заглушками: они выводят своё имя
и полученные аргументы, но не обращаются к файловой системе.

### 2.2. Параметры командной строки (этап 2)

| Параметр | Назначение |
| --- | --- |
| `--vfs <путь>` | Директория на диске, из которой загружается виртуальная файловая система |
| `--script <путь>` | Файл с командами эмулятора, выполняемыми при запуске |

Порядок параметров значения не имеет, оба необязательны: без них эмулятор
запускается в интерактивном режиме с пустой VFS.

При запуске эмулятор выводит отладочное сообщение со всеми заданными
параметрами; незаданный параметр показывается как «не задан»:

```
Параметры запуска:
  VFS:    vfs-samples/minimal
  Скрипт: scripts/stage2-basic.txt
```

При неверных параметрах эмулятор показывает диалог с описанием ошибки
и завершается с кодом 1, не открывая окно.

### 2.3. Стартовые скрипты (этап 2)

Стартовый скрипт — текстовый файл с командами эмулятора, по одной в строке.
Команды выполняются последовательно. При выполнении на экране отображается
как ввод, так и вывод, что имитирует диалог с пользователем.

Ошибочная строка не прерывает выполнение: эмулятор сообщает об ошибке
и переходит к следующей команде.

### 2.4. Виртуальная файловая система (этап 3)

Источником VFS является директория на диске пользователя. При запуске её
содержимое целиком считывается в память, после чего все операции выполняются
только с этой копией. Исходная директория не изменяется.

Поддерживается произвольная вложенность каталогов. Команды `mv` и `mkdir`
меняют состояние VFS в памяти, на диск изменения не записываются.

### 2.5. Разбор аргументов в кавычках

Парсер разбивает введённую строку на имя команды и список аргументов. Аргумент
может быть заключён в одинарные или двойные кавычки — тогда пробелы внутри него
не считаются разделителями. Сами кавычки являются разметкой и в результат
не попадают. Повторяющиеся пробелы между аргументами игнорируются.

| Ввод | Результат разбора |
| --- | --- |
| `cd docs downloads` | команда `cd`, два аргумента |
| `cd "My Documents"` | команда `cd`, один аргумент `My Documents` |
| `ls 'one two' three` | команда `ls`, аргументы `one two` и `three` |
| `ls    -la` | команда `ls`, один аргумент `-la` |
| `ls ""` | команда `ls`, один пустой аргумент |
| `echo a"b c"d` | команда `echo`, один аргумент `ab cd` |

### 2.6. Обработка ошибок

| Ситуация | Сообщение | Этап |
| --- | --- | --- |
| Незакрытая кавычка | `Ошибка разбора: Незакрытая кавычка: <строка>` | 1 |
| Неизвестная команда | `<имя>: команда не найдена` | 1 |
| Лишние аргументы у `cd` | `cd: слишком много аргументов` | 1 |
| Аргументы у `exit` | `exit: команда не принимает аргументов` | 1 |
| Ошибка в строке стартового скрипта | Сообщение об ошибке, выполнение продолжается | 2 |
| VFS не найдена или имеет неверный формат | Сообщение об ошибке загрузки | 3 |
| Скрипт не найден или не читается | `Ошибка выполнения скрипта: не удалось прочитать <путь>` | 2 |
| Неизвестный параметр запуска | `Неизвестный параметр: <имя>` | 2 |
| Параметр запуска без значения | `У параметра <имя> не указано значение` | 2 |
| Путь в VFS не существует | `<команда>: <путь>: нет такого файла или каталога` | 4 |

Пустой ввод игнорируется без сообщения.

### 2.7. Функции по пакетам

#### Пакет `parser`

**Класс `CommandParser`** — разбор введённой строки.

| Функция | Описание |
| --- | --- |
| `ParsedCommand parse(String line)` | Разбирает строку на имя команды и аргументы. При пустом вводе возвращает объект с пустым именем. Бросает `ParseException` при незакрытой кавычке |
| `List<String> tokenize(String line)` | Разбивает строку на токены посимвольно, с учётом кавычек. Приватная |

**Класс `ParsedCommand`** — результат разбора, неизменяемый контейнер.

| Функция | Описание |
| --- | --- |
| `ParsedCommand(String name, List<String> args)` | Конструктор, сохраняет имя команды и её аргументы |
| `String getName()` | Возвращает имя команды |
| `List<String> getArgs()` | Возвращает список аргументов |
| `boolean isEmpty()` | Возвращает `true`, если имя пустое, то есть ввод был пустым |

**Класс `ParseException`** — ошибка разбора, наследник `Exception`.

| Функция | Описание |
| --- | --- |
| `ParseException(String message)` | Конструктор, передаёт сообщение об ошибке в родительский класс |

#### Пакет `commands`

**Интерфейс `Command`** — контракт команды.

| Функция | Описание |
| --- | --- |
| `String execute(List<String> args)` | Выполняет команду и возвращает текст для вывода. Пустая строка означает «ничего не выводить» |

**Класс `CommandRegistry`** — сопоставление имён команд их реализациям.

| Функция | Описание |
| --- | --- |
| `CommandRegistry()` | Конструктор, регистрирует доступные команды |
| `boolean contains(String name)` | Проверяет, зарегистрирована ли команда с таким именем |
| `Command get(String name)` | Возвращает реализацию команды или `null` |
| `void register(String name, Command command)` | Регистрирует команду под указанным именем |

**Реализации `Command`** — по одному классу на команду.

| Класс | Описание | Этап |
| --- | --- | --- |
| `LsCommand` | Возвращает `ls` и аргументы в кавычках через запятую | 1 |
| `CdCommand` | При числе аргументов больше одного возвращает сообщение об ошибке, иначе `cd` и аргумент | 1 |
| `ExitCommand` | При непустых аргументах возвращает сообщение об ошибке, иначе завершает работу приложения | 1 |
| `CalCommand` | Выводит календарь на указанный месяц | 4 |
| `EchoCommand` | Выводит аргументы через пробел | 4 |
| `TailCommand` | Выводит последние строки файла из VFS | 4 |
| `MvCommand` | Перемещает файл или каталог внутри VFS | 5 |
| `MkdirCommand` | Создаёт каталог в VFS | 5 |

#### Пакет `gui`

**Класс `EmulatorFrame`** — окно эмулятора, наследник `JFrame`.

| Функция | Описание |
| --- | --- |
| `EmulatorFrame(EmulatorConfig config)` | Конструктор. Задаёт заголовок, размер и положение окна, собирает интерфейс, выводит приветствие, параметры запуска и приглашение |
| `void runStartScript()` | Выполняет стартовый скрипт, если он задан; при ошибке чтения печатает сообщение. Вызывается после показа окна |
| `void printConfig()` | Выводит параметры запуска или пометку «не задан» |
| `void runScriptLine(String line)` | Обрабатывает одну строку скрипта: печатает её после приглашения, выполняет и печатает новое приглашение |
| `JScrollPane buildOutputArea()` | Настраивает область вывода и оборачивает её в панель с прокруткой |
| `JPanel buildInputPanel()` | Собирает нижнюю панель: подпись, поле ввода и кнопку отправки |
| `void onSubmit(ActionEvent event)` | Обработчик нажатия Enter и клика по кнопке. Читает ввод, очищает поле, выполняет команду, печатает новое приглашение |
| `void runLine(String line)` | Разбирает строку, обрабатывает ошибки разбора, пустой ввод и неизвестную команду, выполняет найденную команду |
| `void printLine(String text)` | Выводит строку с переводом строки и прокручивает область вывода вниз |
| `void print(String text)` | Выводит строку без перевода строки |
| `String promptText()` | Формирует приглашение вида `username@hostname:~$` |
| `String buildTitle()` | Формирует заголовок окна вида `Эмулятор - [username@hostname]` |
| `String userName()` | Возвращает имя пользователя из системного свойства `user.name` |
| `String hostName()` | Возвращает имя хоста; при ошибке определения возвращает `unknown-host` |

Публичные — конструктор и `runStartScript`, остальные приватные.

**Класс `Main`** — точка входа.

| Функция | Описание |
| --- | --- |
| `void main(String[] args)` | Разбирает параметры командной строки, создаёт и показывает окно в потоке диспетчеризации событий Swing, затем запускает стартовый скрипт |
| `void reportArgsError(String message)` | Показывает диалог с описанием ошибки параметров и подсказкой по использованию, затем завершает работу с кодом 1 |

#### Пакет `config` (этап 2)

| `ArgsException` | Ошибка разбора параметров: неизвестный параметр или параметр без значения |

#### Пакет `script` (этап 2)

#### Пакет `vfs` (этап 3)

## 3. Описание команд для сборки проекта и запуска тестов

Требуется JDK 21 или новее. Внешних библиотек не нужно. Сборка выполняется
с флагом `--release 21`, поэтому байт-код не зависит от версии JDK,
установленной на машине.

### 3.1. Linux и macOS

| Команда | Действие |
| --- | --- |
| `./run.sh` | Собирает проект в каталог `out` и запускает эмулятор |
| `./test.sh` | Собирает проект и тесты, запускает тесты |

Если скрипты не запускаются, выдайте им право на исполнение:

```bash
chmod +x run.sh test.sh
```

### 3.2. Windows

| Команда | Действие |
| --- | --- |
| `run.bat` | Собирает проект в каталог `out` и запускает эмулятор |
| `test.bat` | Собирает проект и тесты, запускает тесты |

### 3.3. Запуск с параметрами (этап 2)

```bash
java -cp out Main --vfs vfs-samples/minimal --script scripts/stage2-basic.txt
```

Скрипты `run.sh` и `run.bat` запускают эмулятор без параметров. Чтобы передать
параметры, вызывайте `java` напрямую после сборки.

Проверить все сочетания параметров разом:

```bash
./scripts/run-configs.sh
```

Этот скрипт собирает проект и восемь раз запускает эмулятор: без параметров,
с каждым параметром по отдельности, с обоими сразу, со скриптом ошибок,
с несуществующим скриптом и с двумя видами неверных параметров.

### 3.4. Результат запуска тестов

```
OK   имя команды без аргументов
OK   аргументов нет
OK   имя команды с аргументами
OK   число аргументов
OK   первый аргумент
OK   второй аргумент
OK   двойные кавычки дают один аргумент
OK   кавычки убраны, пробел сохранён
OK   одинарные кавычки: число аргументов
OK   одинарные кавычки: первый аргумент
OK   одинарные кавычки: второй аргумент
OK   повторяющиеся пробелы игнорируются
OK   аргумент после лишних пробелов
OK   строка из пробелов считается пустой
```

Запускаются два набора: 17 проверок разбора строки и 14 проверок разбора
параметров командной строки. После каждого выводится «Все проверки пройдены».

При провале хотя бы одной проверки выводится строка `FAIL` с ожидаемым
и полученным значением, а процесс завершается с кодом 1. Тесты написаны
без внешних библиотек, чтобы запуск требовал только JDK.

## 4. Примеры использования

### 4.1. Интерактивный режим

После запуска открывается окно эмулятора. Пример сессии, демонстрирующий
реализованные возможности и обработку ошибок:

```
Эмулятор запущен. Введите команду.
user@host:~$ ls
ls
user@host:~$ ls -la /home
ls "-la", "/home"
user@host:~$ cd docs
cd "docs"
user@host:~$ cd "My Documents"
cd "My Documents"
user@host:~$ ls 'one two' three
ls "one two", "three"
user@host:~$ ls    -la
ls "-la"
user@host:~$ frobnicate
frobnicate: команда не найдена
user@host:~$ cd docs downloads
cd: слишком много аргументов
user@host:~$ exit abc
exit: команда не принимает аргументов
user@host:~$ cd "unterminated
Ошибка разбора: Незакрытая кавычка: cd "unterminated
user@host:~$ exit
```

Аргументы выводятся в кавычках, чтобы были видны их границы: по выводу
`cd "My Documents"` сразу понятно, что аргумент один, а не два.

### 4.2. Выполнение стартового скрипта (этап 2)

```bash
java -cp out Main --script scripts/stage2-basic.txt
```

Окно открывается и само прогоняет команды из файла, показывая и ввод, и вывод:

```
Эмулятор запущен. Введите команду.
Параметры запуска:
  VFS:    не задан
  Скрипт: scripts/stage2-basic.txt
user@host:~$ ls
ls 
user@host:~$ ls -la /home
ls "-la", "/home"
user@host:~$ cd docs
cd "docs"
user@host:~$ cd "My Documents"
cd "My Documents"
user@host:~$ ls 'one two' three
ls "one two", "three"
user@host:~$ 
```

Ошибочная строка не прерывает выполнение — скрипт `scripts/stage2-errors.txt`
содержит неизвестную команду, лишние аргументы и незакрытую кавычку, и после
каждой из них выполнение продолжается со следующей строки.

## Структура репозитория

```
.
├── src/
│   ├── Main.java                     точка входа
│   ├── gui/EmulatorFrame.java        окно эмулятора
│   ├── parser/
│   │   ├── CommandParser.java        разбор строки на команду и аргументы
│   │   ├── ParsedCommand.java        результат разбора
│   │   └── ParseException.java       ошибка разбора
│   ├── commands/
│   │   ├── Command.java              интерфейс команды
│   │   ├── CommandRegistry.java      реестр команд
│   │   ├── LsCommand.java
│   │   ├── CdCommand.java
│   │   └── ExitCommand.java
│   ├── config/
│   │   ├── EmulatorConfig.java       параметры запуска
│   │   ├── ArgsParser.java           разбор командной строки
│   │   └── ArgsException.java        ошибка разбора параметров
│   ├── script/
│   │   └── ScriptRunner.java         выполнение стартового скрипта
│   └── vfs/                          виртуальная файловая система (этап 3)
├── tests/
│   ├── parser/CommandParserTest.java проверки разбора строки
│   └── config/ArgsParserTest.java    проверки разбора параметров
├── scripts/
│   ├── stage2-basic.txt              скрипт эмулятора: обычный проход
│   ├── stage2-errors.txt             скрипт эмулятора: обработка ошибок
│   ├── run-configs.sh                запуск с разными параметрами (Linux/macOS)
│   └── run-configs.bat               то же для Windows
├── vfs-samples/                      варианты VFS для тестирования (этап 3)
├── run.sh / run.bat                  сборка и запуск
├── test.sh / test.bat                сборка и запуск тестов
├── .gitignore
├── .gitattributes                    переводы строк для .sh и .bat
└── README.md
```
